# Code map — execution boundaries

Use the [Hivest workflow](../../skills/hivest-portfolio-ai/references/workflow.md) for programme sequencing. For new independent cases, the [standalone skill](../../skills/standalone-company-analysis/SKILL.md) describes the procedure and the [case runtime](../agent/case-process.md) enforces the stage contracts. The historical `companies/` route does not acquire A0–A4 receipts retroactively ([ADR-0002](ADR-0002-case-process.md)).

| Component | Capability | Boundary |
|---|---|---|
| [Hivest programme state](../../program/state.json) and company manifest/index | Track portfolio scope and progress. Use the Hivest workflow to select the next procedure. | Independent runs use `program_ref=null` and stay outside Hivest roll-ups. |
| [Portable session checkpoint](../agent/context-and-resume.md) | The [checkpoint schema](../../contracts/session-checkpoint.schema.json) records `next_action` and pinned inputs. The [resume command](../../scripts/session_checkpoint.py) returns the next action after checking the independently observed repository SHA and pinned bytes. | Read-only handoff. `READY_TO_RESUME` neither updates case state nor approves or promotes outputs. |
| [Company package](../../contracts/company-package.schema.json) | Records source and fragment SHA-256 fingerprints, capture kind and hash scope, and the links to claims. [Package validation](../../scripts/validate.py) checks fragment fingerprints. | Metadata and fragment checks do not verify the captured source bytes. |
| Source capture integrity | With an archive, the [bundle validator](../../scripts/validate_bundle.py) checks captured source bytes against their declared hashes. [Pre-HITL checks](../../scripts/check_prehitl.py) also require originals for material sources. | Without an archive, bundle validation reports `not_checked_external_archive_required`. An excerpt hash does not prove integrity of the original. |
| `research_graph.py` | Dependency context and affected nodes | No web research, graph initialization or automatic rewrite |
| Standalone analysis skill | Guides routing and composition of the three-page output | Procedure only; no `Agent.py` orchestrator exists |
| [Case runtime](../../scripts/case_runtime.py) | Initializes an isolated case and its graph before collection; validates inputs, outputs and dependencies as the agent begins and completes A0–A4 | The agent gathers evidence and makes judgments. The runtime checks submitted artifacts and records attempts. Inspect the live case with `case_runtime.py status`; its `state.json` is the authority for stages and attempts. |
| [Case manifest](../../workflow/case-process.json) and contracts | The manifest defines stage order and dependencies; the [manifest schema](../../contracts/case-process.schema.json) constrains it and the [artifact schema](../../contracts/case-artifacts.schema.json) defines stage data | The [engine release](../../workflow/engine-release.json) pins the shared implementation and schemas; it does not define this repository’s stage order. |
| [Template capability registry](../../templates/registry.json) | Declares the capabilities of each template/profile pair, including previews and schema-only entries. Its [checker](../../scripts/check_template_registry.py) validates the inventory and references. | A registry entry does not select a case renderer or authorize committee release. See [template binding](template-binding.md) for the capability map. |
| [Independent case template profile](../../workflow/case-process.json#templates) | The manifest resolves the intake template ID to a profile. The [runtime](../../scripts/case_runtime.py) checks that its payload schema and renderer are among the pinned references and validates the schema. | An unknown template or a render request without an executable adapter is rejected before the case is created. |
| [Artifact receipt](../agent/artifact-receipts.md) | The [schema](../../contracts/artifact-receipt.schema.json) records the artifact location, integrity, QA, persistence and authorization metadata separately. | The [receipt validator](../../scripts/validate_artifact_receipt.py) requires independently re-read bytes with the same SHA-256 for `published_verified`. It does not publish the artifact or authenticate a decision. |
| [Publication preflight](../agent/publication-preflight.md) | The [preflight](../../scripts/publication_preflight.py) checks the receipt, PDF bytes, freeze evidence and reader review. | Even if all checks pass, it returns `AWAIT_AUTHENTICATED_HUMAN_RELEASE` and `committee_authorized=false`. Only the authorized human workflow can release the artifact to the committee. |
